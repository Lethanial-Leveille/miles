| Active streaming cascade | Stream capture after activation. Compare Nova 3 streaming with the same endpoint, then Flux turn detection with a bounded fallback. Moving the brain itself would be a separate architecture decision.

## Devices and failure behavior

Have the active device own the microphone and speaker for a turn. Use a short server lease per principal and conversation, explicit takeover, and a generation number so old audio is dropped. Preserve committed conversation state and receipts across handoff. Keep guest or phone sessions scoped. During a partition, each device can offer its own local responses within an explicitly limited capability set. Reconnection restores the authoritative session and invalidates stale drafts. Use bounded audio buffers, sequence numbers, a reconnect budget, and a visible or audible failed turn prompt. Resume from confirmed playback or ask for the last sentence again where exact playback cannot be confirmed.

## Benchmark and decision thresholds

Use the [testing ladder](TESTING.md). First, validate measurement and fault handling with synthetic fixtures in an isolated environment. Then run a real time, consented audio replay with synthetic names, calendar fixtures and endpoints that simulate outcomes. Keep recordings outside Git under the project’s private data rules. Collect separate approved acoustic validation on the actual devices before claiming any device result. Use the same input clips, speech end labels, context snapshots, tool responses and voice settings across contenders. Use both clean audio injection for stage attribution and acoustic playback for the whole path.

1. Build a small fixed screening corpus and a disjoint, blinded evaluation set. Include ordinary dialogue, short commands, long questions with planning pauses, negations and corrections, context and memory questions, named entities, numbers, short follow ups, intentional interruption, coughs and other voices, tool reads, approved and refused writes using stubs, provider failures, loss of internet, loss of LAN and reconnection. Preserve an identical text only lane for typed use. Include onset clipping and accidental wake tests outside the answer latency denominator.
2. Use paired randomized order and fixed traces for transport loss and jitter. Separate clean, far field or noisy, Bluetooth, cellular, telephone codec, cold start and warm reuse runs. Record hardware, OS and firmware, route, firmware audio path, provider region and model revision, cache state and network RTT. Measure actual WiFi, cellular and BLE when authorized. Emulated delay alone belongs in a separate result. Screen with at least 40 paired turns. For finalists aim for at least 200 per primary latency cohort, report confidence intervals and sample counts, and keep rare failures visible as explicit outcomes.
3. Annotate the last intentional speech sample with an input and output acoustic reference on one clock. Annotate acknowledgments and first answer bearing audio separately. A chime, filler or “I’ll check” is acknowledgment. A grounded fact, clarification question, or truthful completion report is meaningful. Tool time to final ground truth is a separate metric. Use device monotonic durations and trace IDs for capture, partial and final transcript, verification, context, model text, tool call and receipt, safe text ready, first synth bytes, first decoded frame, output and interruption. Do not subtract unsynchronized host clocks. Capture failures and timeouts, report completion and no response rates alongside successful p50 and p95, and retain the cost of all attempts.
4. Compare normalized WER on speech, exact command slots, false speech on silence and early commits. Score conversation against answer and memory rubrics, and tool calls against exact fixtures and authorization state. Use blinded randomized voice audition across several renditions of each line. Measure energy, CPU, RSS, dropped and underrun frames, thermal throttling and reconnect time under a sustained run and in idle. Record only scope and operation outcomes in shared results.

The numbers below are initial research targets and promotion gates. Revisit them after obtaining a real baseline and sizing the study for the accuracy margins.

| Metric | Initial target |
|---|---|
| First meaningful audible speech after actual user speech end | Warm ordinary turns without tools p50 ≤ 1.5 s and p95 ≤ 2.8 s on room and active WiFi app. Initial cellular or telephone target p50 ≤ 2.0 s and p95 ≤ 3.5 s. Subsecond median on suitable warm turns is aspirational. |
| Local deterministic and acknowledgment | Supported local commands p50 ≤ 0.8 s and p95 ≤ 1.5 s on a candidate endpoint. Measure activation acknowledgment separately, target p95 ≤ 250 ms. For a slow committed lookup, measure any progress acknowledgment independently, target p95 ≤ 1.5 s after speech end. |
| Tool result and interruption | Warm routine read tools p50 ≤ 2.5 s and p95 ≤ 5 s to meaningful result as an initial target. Report slow or complex tools separately, including provider time and honest failure. Barge in from interrupt speech onset to audible stop p50 ≤ 250 ms and p95 ≤ 450 ms, with ≥ 95% caught and ≤ 1 false stop per 100 negative trials. |
| STT and turn integrity | Speech only WER within 1 percentage point of the paired baseline, with no systematic loss on short follow ups or names and numbers. Exact critical slots ≥ 98% on supported commands and early commits ≤ 1%, with no dangerous clipping or mistaken permission elevation in the challenge set. |
| Answer and tool accuracy | ≥ 95% rubric pass on ordinary, correction and recall cases, with a margin of at most two percentage points against control. All expected authorization and confirmation decisions correct on the fixture set. Zero premature writes, duplicate effects, protected writes or false reports of success in replay and disconnect tests. |
| Naturalness and resources | Owner accepts voice identity and prefers the candidate or judges it equivalent in a blind audition. Mean naturalness within 0.25 on a five point scale, with continuity rated separately. Zero sustained thermal throttling, extra idle battery drain initially ≤ 1 percentage point/hour on mobile versus matched idle, incremental active local model RSS target ≤ 512 MiB on Pi, and < 1% turns with underruns on a sustained run. |
| Cost and recovery | Aim for usage cost per successful exchange at or below control. Allow up to 15% only for a clear quality preserving speed gain with owner acceptance. Target zero billed idle audio. Reconnect and restore a usable active session within five seconds at p95 after transport returns, with no stale audio or duplicate effects. |

The fixed endpoint, physical audio buffers, connection setup, provider queues and multi round tools all impose floors. Continuous capture can hide upload and inference but cannot remove an ambiguous pause, a long tool response, or an outage. Cell handovers and Bluetooth route changes belong in tail and recovery results. Report each cohort even if its target proves impractical.

Low value work includes globally shortening the silence timeout, rerunning earlier lightweight Whisper decoders without a new accuracy hypothesis, optimizing prompt opening length before measuring safe text ready, warming connections already reused, indiscriminate tool parallelism and continuous paid listening. Remove the whole reply dependency before investing in a new low latency codec for the app. Provider queue spikes and carrier buffering can be mitigated with bounded fallback and cancellation, and remain outside MILES’ direct control. Telephony and Halo trials follow a proven media and interruption path and their own capability checks.

## Other research directions

- **Offline intelligence.** Expand supported local commands and scoped, freshness labeled recall. Evaluate Mac hosted or device local inference on a bounded personal task set when the voice path is stable. Preserve clear degradation for live data and actions. [Failure boundaries](BRAIN.md#failure-boundaries)
- **Unfinished intentions.** Explore explicit, editable records for interrupted plans, resumption cues and expiry. Reuse the distinction between heard and unheard reply text. A remembered intention does not supply consent later. [Interrupted reply work](BACKEND_TODO.md#resuming-a-reply-he-cut-off-partly-built-oct-30-2026)
- **Anticipatory preparation and initiative.** Prepare relevant read only context or drafts within existing permission, freshness and privacy limits. Prefer timely information, selective advice, respectful execution and optional accountability. Let the owner choose when to revisit a decision and avoid repeated unsolicited disagreement. Personality, initiative and device presence grant no execution rights. [Accountability research](BACKEND_TODO.md#accountability-she-notices-she-does-not-ask-planned-oct-2-2026) · [Approved roadmap](ROADMAP.md)
- **Wearables.** Treat AirPods and Halo as device experiences with explicit activation and handoff. Study interruption, comfort, battery and private delivery before ambient or proactive features. [Project direction](../README.md)
